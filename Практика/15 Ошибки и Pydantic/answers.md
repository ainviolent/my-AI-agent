# День 15 — ответы на контрольные вопросы

1. **Для чего используется try?**

   В try записывают действие, при котором возможна ошибка.

2. **Для чего используется except?**

   except обрабатывает указанный тип ошибки.

3. **Что означает Exception as error?**

   Объект возникшей ошибки сохраняется в переменную error.

4. **Почему пользователю лучше не показывать длинную техническую ошибку?**

   Короткое сообщение понятнее пользователю; технические сведения остаются в журнале.

5. **Что означает код 401?**

   401 означает ошибку авторизации: проверьте ключ или токен.

6. **Что означает код 429?**

   429 означает превышение лимита запросов.

7. **Что обычно означает код 500?**

   500 обычно означает внутреннюю ошибку сервиса.

8. **Что такое логирование?**

   Логирование — запись событий программы.

9. **Для чего нужен app.log?**

   app.log помогает понять, на каком этапе произошла ошибка.

10. **Что означает уровень INFO?**

   INFO — обычное событие, например успешное получение ответа.

11. **Что означает уровень WARNING?**

   WARNING — предупреждение, например пустой ввод.

12. **Что означает уровень ERROR?**

   ERROR — ошибка, например неудачный вызов API.

13. **Почему API-ключ нельзя записывать в лог?**

   Ключ даёт доступ к API; запись в журнал может раскрыть его посторонним.

14. **Что делает strip()?**

   strip() удаляет пробельные символы по краям строки.

15. **Зачем проверять пустой ввод?**

   Чтобы не отправлять бессмысленный запрос и не расходовать лимит API.

16. **Что такое структурированный ответ?**

   Это ответ с заранее заданными полями и типами.

17. **Чем структурированный ответ удобнее обычного текста?**

   Поля можно читать напрямую, без поиска значений в произвольном тексте.

18. **Что такое Pydantic?**

   Pydantic описывает и проверяет структуру данных.

19. **Для чего используется BaseModel?**

   BaseModel — базовый класс для описания модели данных.

20. **Что означает запись score: int?**

   Поле score должно содержать целое число.

21. **Для чего используется Field(description=...)?**

   Описание поясняет назначение поля и помогает сформировать схему для модели.

22. **Что делает chat_parse()?**

   chat_parse() получает ответ и разбирает его в объект Pydantic.

23. **Что означает response_format=Result?**

   В response_format передаётся класс схемы Result.

24. **Для чего используется strict=True?**

   strict=True запрашивает строгую схему структурированного ответа; проверка результата всё равно необходима.

25. **Что находится в parsed?**

   В parsed находится проверенный объект выбранной Pydantic-модели.

26. **Как получить значение конкретного поля Pydantic-объекта?**

   Через точку: parsed.topic или parsed.summary.

27. **Что нужно сделать, если structured output вызвал ошибку?**

   Перехватить исключение, сообщить об ошибке и записать безопасные технические сведения в лог.
